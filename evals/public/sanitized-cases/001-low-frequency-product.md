# Case 001 — Low-frequency product

- **ID**: 001
- **Type**: Claim
- **Input** (visible to the Agent only):
  ```text
  WiFi Lens is a low-frequency tool, so it is inherently hard to retain users.
  ```
- **Context** (visible to the Agent only):
  ```text
  The user is an indie developer. The product WiFi Lens is a WiFi tool.
  Weekly retention is about 3%; they are deciding on product direction.
  ```
- **Expected type**: positive (cognitive exploration)

## Checkpoints (evaluator use only — do not provide to the Agent under test)

- [ ] Does it distinguish "current product state" (low retention) from "category essence" (inherently low-frequency)?
- [ ] Does it discover the possibility of professional high-frequency users (network admins / retail-store IT / …)?
- [ ] Does it identify "continuous monitoring" vs "fault diagnosis" as two different product categories?
- [ ] Does it ultimately design a reality verification (rather than stopping at abstract discussion)?
- [ ] Does it produce a newly discovered unknown?
